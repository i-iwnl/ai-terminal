## 3. 技術的制約・前提条件

- **鉄則4/5（外部フォーマットの防御）**: CLI が返した生の `status` を隠さない。表示は翻訳しつつ、生の値をメタ情報として残す。未知の値を既知の2値のどちらかに丸めない
- **E2E が現在の実装に依存している**:
  - `S12-task-list.spec.ts` が `.task-item--busy` / `.task-item--idle` をセレクタとして使い、`.task-item__meta` に `busy` / `idle` の文字列が含まれることを検証している
  - `screenshots.spec.ts:566,572` が同じクラスを撮影対象にしている
  - クラス名を変えるなら、この2ファイルを同一コミットで追従させる
- **`make e2e-lint`（check2）**: spec を新規追加する場合のみ `scenarios.yml` の追記が必要。今回は既存 spec の編集のみで、シナリオ台帳のタイトルも変わらないため追記は不要
- **撮り直しの検出は機械化されていない**: 台帳ハーネスは画像の存在しか見ない。`docs/images/S12-task-list.png` の撮り直しは人手で担保する
