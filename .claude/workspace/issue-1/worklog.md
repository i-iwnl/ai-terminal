- `@playwright/test` を devDependency に追加（**未コミット**）

### 設計判断

- **隔離ハーネス方式（一時 HOME + PATH 先頭の偽 CLI）を採用**: このアプリは実 OS に触るため、素直に書くと (1) 実行のたびに結果が変わる（別ターミナルで claude を動かしていると一覧が変化する）、(2) **スクリーンショットに実プロジェクト名や実プロンプトが写り込む**。後者は README に載せる画像としては事故になる。アプリ本体にテスト用の分岐を入れる案もあったが、本番コードにテスト専用コードを残さない方を選んだ
- **偽 CLI は受け取った引数を出力する設計にする**: これにより `--session-id` や `--resume` が正しく渡ったかまで検証できる。単に固定出力を返すだけだと「アプリが CLI をどう呼んだか」が検証できない
- **シナリオ管理はレジストリ + lint**: `e2e/scenarios.yml` を唯一の正とし、`scripts/lint-e2e.mjs` で spec との 1:1 を機械検査する。`.claude/scripts/lint-skills.sh` と同じ「規約を文章ではなく機械に守らせる」思想
- **スクリーンショットの注釈は DOM オーバーレイ注入で行う**: 撮影直前に番号バッジ・矢印・日本語キャプションを DOM に差し込んでから撮る。画像処理ライブラリを追加せずに済み、文言の修正がコードの1行変更で済む
- **CI には載せない（ローカル実行のみ）**: Electron の GUI テストは Linux ランナーで xvfb が必要になり、macOS ランナーは高価。既存 CI（typecheck / lint / build）は軽いまま保つ

### 教訓

- **DevTools を開かないと見えない不具合がある。** preload の読み込み失敗は Renderer のコンソールにしか出ず、ターミナル側には一切出力されない。「ウィンドウが開いた＝起動成功」という確認は不十分だった。E2E で最初に潰すべきはここ（S01/S02 がこれに対応する）
- node-pty の `spawn-helper` は npm install で実行権限が落ちることがあり、`posix_spawnp failed` という原因の分かりにくいエラーになる。`postinstall` で復元しているが、**CI やコンテナで環境を作り直すたびに再発しうる**ので、E2E の実行前提として意識しておく

## 2026-07-27 - E2E 基盤の実装完了と、それが見つけたアプリのバグ

### 実施内容

- 隔離ハーネス（一時 HOME + PATH 先頭の偽 CLI + JSONL フィクスチャ）を実装
- `e2e/scenarios.yml` をシナリオの唯一の正として確定。`scripts/lint-e2e.mjs` で spec との 1:1 を機械検査
- **S01 から S22 まで全22 spec が green**（当初21件 + IME の S22 を追加）
- スクリーンショット11枚を撮影し、README に画像付きの使い方ガイドを追加
- `.claude/skills/e2e/` として運用を skill 化

### 設計判断

- **IME はテストできると判明したので S22 を追加した。** 当初「OS レベルの入力なので自動化不能」と判断していたが、Chromium の DevTools Protocol に `Input.imeSetComposition` があり、Electron 経由で叩ける。変換中の文字列が `.composition-view` に出るところまで検証できる。ただし macOS の入力メソッドとの実際の相互作用は再現していないので、手動チェックリストは残す
- **`--disable-gpu` で Electron を起動する。** そうしないと xterm が WebGL レンダラになり、文字が canvas に描かれて DOM から読めない。GPU を無効にするとアプリの try/catch が DOM レンダラにフォールバックし、テキストを検証できるようになる。副次的に「WebGL が使えない環境でも動く」ことの検証にもなっている
- **偽 CLI は受け取った引数を出力する。** これにより `--session-id` や `--resume` が正しく渡ったかを画面から検証できる

### 教訓

- **E2E がアプリの実バグを1件見つけた。** タブを開いた直後の PTY 出力が、Renderer が購読を始める前に届いて失われていた。AI CLI の起動バナーが消え、ターミナルが空のまま何も起きないように見える。`src/renderer/src/terminal/ptyStream.ts` を新設し、購読者がいない ptyId の出力をバッファして購読開始時にフラッシュする形で修正。修正後、実行時間が 49 秒から 17 秒に短縮された（競合による待ちが消えたため）
- **壊れた JSONL で `parseError` が付いていなかった**（全行がパース不能でも例外が出ないため）。壊れたセッションが「中身の無い正常なセッション」と区別できない状態だった。設計方針（壊れたエントリを隠さない）に反するので `src/main/history/reader.ts` を修正
- **フィクスチャを推測で書くと、間違った形を検証してしまう。** `ai-title` 行のキーを `title` と書いたが、実データ330ファイルを走査したところ正解は `aiTitle` だった。アプリの実装が正しく、フィクスチャが誤っていた。**外部フォーマットのフィクスチャは、書く前に実データを走査して確認すること**
- **macOS の一時ディレクトリは `/var` 配下だが `/var` は `/private/var` へのシンボリックリンク。** OS の `getcwd()` は正規化した側を返すため、`realpathSync` を取らないとアプリの探すパスとずれる
- **Electron の userData は HOME の差し替えを無視する。** `--user-data-dir` を分けないとテスト間で状態が混ざる
- **スクリーンショットは撮って終わりにしない。** 「コマンドを打てば結果が返る」と説明した画像に出力行が写っていない、注釈が対象の文字を覆っている、といった食い違いが3枚あった。1枚ずつ目で見て、キャプションの主張が画像から確認できるかを検証する必要がある
- シェルのプロンプトを固定しないと、実マシンのユーザー名とホスト名がスクリーンショットに写り込む
