## 3. 技術的制約・前提条件

- **アプリのコードを変更せずに決定論を得る。** テスト専用の分岐を Main プロセスに入れない。制御は `HOME` と `PATH` の差し替えだけで行う
- **実データを一切参照しない。** `~/.claude/projects` の実履歴と `claude agents --json` の実セッションに触れると、結果が不安定になるうえスクリーンショットに実プロジェクト名が写る
- 検証コマンドの唯一の正はルート `CLAUDE.md`（ここには再掲しない）
- 開発起動時は DevTools が自動で開くが、E2E はビルド済みアプリを起動するため `ELECTRON_RENDERER_URL` が未設定になり DevTools は開かない
- `node-pty` の `spawn-helper` に実行権限が必要（`postinstall` で復元される）。環境を作り直した直後は要注意

## 4. 設計判断履歴

| 日付 | 判断 | 根拠 | 代替案 |
|---|---|---|---|
| 2026-07-27 | 一時 HOME + PATH 先頭の偽 CLI で隔離する | アプリのコードを変えずに決定論を得られ、スクリーンショットへの実データ写り込みも防げる | アプリに環境変数でのテストモードを入れる案。本番コードにテスト専用の分岐が残るため却下 |
| 2026-07-27 | 偽 CLI は受け取った引数を出力する | `--session-id` や `--resume` が正しく渡ったかを検証できる | 固定出力のみを返す案。アプリが CLI をどう呼んだかを検証できないため却下 |
| 2026-07-27 | シナリオはレジストリ + lint で 1:1 を強制 | シナリオを足して spec を書き忘れる（逆も）を機械的に落とせる | 命名規約だけで運用する案。人間の注意力に依存するため却下 |
| 2026-07-27 | スクリーンショットの注釈は DOM オーバーレイ注入 | 画像処理ライブラリを増やさずに済み、文言修正がコード変更だけで完結する | 画像処理ライブラリで後から描き込む案。依存とビルド手順が増えるため却下 |
| 2026-07-27 | CI には載せずローカル実行のみ | Linux ランナーでは xvfb が必要、macOS ランナーは高価。既存 CI を軽く保つ | CI で回す案。将来必要になったら `.github/workflows/ci.yml` にジョブを追加する |
| 2026-07-27 | E2E が見つけたアプリ本体のバグ2件は、この Issue の中で直す | テストを green にするための迂回（spec 側で待つ・期待値を緩める）で通すと、本物のバグを隠すことになる。E2E を入れる目的そのものに反する | 別 Issue に切り出す案。E2E の spec が「壊れたまま通る」期間ができるため却下。ただしコミットは分けた（`cd76001`） |
