## 5. E2E が `--disable-gpu` 固定のため、WebGL レンダラ経路を一度も検証していない

### 症状

`make dev`（GPU 有効 = WebGL レンダラ）でターミナルが**真っ黒のまま何も描画されない**不具合があったが、E2E 22件は全て green のままだった。

原因は `@xterm/xterm/css/xterm.css` が未 import だったこと（2026-07-28 に修正済み）。canvas を配置するのは xterm.css の規則なので、CSS が無いと WebGL レンダラは何も表示できない。

### 原因

E2E ハーネスは全テストを `--disable-gpu` で起動する（`e2e/fixtures/harness.ts`）。これは「WebGL だと文字が canvas に描かれ DOM から読めない」ため意図的にそうしている。結果として **DOM レンダラ経路しか検証されていない**。

DOM レンダラは文字を実 DOM のテキストノードとして描くため、xterm.css が無くても表示されてしまう。つまりこの不具合は E2E の構造上、原理的に検出できなかった。

### 影響範囲

- ユーザーが実際に使う `make dev` / 本番起動は WebGL レンダラ。**E2E が緑でも実利用時に壊れている**状態がありうる
- 描画品質に関わる不具合全般（文字幅・色・カーソル・選択範囲）

### 対処方針

- [x] 原因となった xterm.css の未 import を修正する
- [x] GPU 有効で起動し、canvas のピクセルを検証するシナリオを追加する -> S23。`launchApp({ gpu: true })` と `e2e/fixtures/pixels.ts` を新設
- [x] `harness.ts` の `--disable-gpu` に、この盲点を明記したコメントを追加する

### 優先度

P1

### ステータス

対処済み。S23 は不具合を再現すると赤くなることを確認済み（xterm.css の import を外して検証）
