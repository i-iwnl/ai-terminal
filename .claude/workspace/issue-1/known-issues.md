## 2. 日本語 IME は自動テストで検証できない

### 症状

変換中の下線表示・確定前の挙動は OS レベルの入力イベントで、Playwright から再現できない。

### 原因

IME の変換処理はブラウザやアプリの外側（OS の入力メソッド）で行われるため。

### 影響範囲

- このアプリで最も壊れやすく、かつ最も重要な機能が自動検証の対象外になる

### 対処方針

- [x] 自動化の対象外と明記する（Issue #1 に記載済み）
- [ ] `.claude/skills/terminal/operations/verify-terminal.md` の手動チェックリストを唯一の検証手段として維持する
- [ ] E2E では「日本語を含む**出力**の文字幅」（S04）までを担保し、入力側は担保しないことを README にも明記する

### 優先度

P1

### ステータス

対処方針確定（自動化しないことを決定）

## 3. tmux 永続化は E2E の範囲外

### 症状

tmux でラップした場合、内側の `claude` が終了しても PTY の exit が発火しない。この挙動と、アプリ再起動を跨いだセッション復帰は E2E で検証できない。

### 原因

アプリのプロセスライフサイクルを跨ぐ検証になるため、単一の Playwright セッションでは表現できない。

### 影響範囲

- tmux 永続化まわり全般
- E2E では `useTmux: false` の固定設定で動かすため、この経路は一切通らない

### 対処方針

- [ ] 必要になったら別途シェルスクリプトでの検証を検討する
- [ ] E2E のフィクスチャでは `useTmux: false` を明示し、意図的に対象外にしていることをコメントで残す

### 優先度

P3

### ステータス

先送り

## 4. macOS 通知は検証手段が無い

### 症状

タスク完了時の macOS 通知の発火を、Playwright から観測できない。

### 原因

OS の通知センターへの表示はアプリの DOM 外で起こるため。

### 影響範囲

- 完了通知（busy から idle への遷移検知）

### 対処方針

- [ ] Main プロセスのログ出力で発火のみを間接的に確認する案を検討する
- [ ] 通知の内容そのものは手動確認に回す

### 優先度

P3

### ステータス

先送り
