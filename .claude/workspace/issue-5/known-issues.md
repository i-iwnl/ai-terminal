## 2. 通知音が実際に鳴ることは自動テストで担保できない

### 症状

`afplay` の起動は投げっぱなしで、音が出たかどうかを観測する手段が無い。E2E で確認できるのは「試聴ボタンを押してもアプリが落ちない」ことまで。

### 原因

音声出力の検証にはオーディオデバイスの観測が必要で、Playwright の射程外。macOS 通知そのものが検証できないのと同じ理由（`issue-1` の `/e2e` skill `reference/limitations.md` に既出）。

### 影響範囲

- 音源パスの解決規則（`resolveSoundPath`）は単体テストで担保できるが、実際の再生経路は未検証
- 音源名は合っているのに鳴らない、という不具合は自動では捕まらない

### 対処方針

- [ ] 手動で確認する: 設定パネルでサウンドを選び「試聴」を押して音が出ること
- [ ] 手動で確認する: 存在しない音源名を `config.json` に直接書いても、通知自体は出ること
- [x] `/e2e` skill の `reference/limitations.md` に「対象外」として記録する

### 優先度

P2

### ステータス

未対処（手動確認が残っている）

## 3. Webhook URL が config.json に平文で保存される

### 症状

Slack / Discord の Incoming Webhook URL は、それ自体が投稿権限を持つ秘密情報だが、`~/.ai-terminal/config.json` に平文で保存される。

### 原因

設定を1つの JSON にまとめる既存の方式をそのまま使ったため。Keychain 等への退避は実装していない。

### 影響範囲

- 設定ファイルを共有・バックアップ・同期した場合に漏れうる
- リポジトリ内のファイルではないため、誤コミットのリスクは低い

### 対処方針

- [x] README の該当節に注意書きを入れる
- [x] 設定パネルの画面上にも「config.json に平文で保存されます」と明記する
- [ ] 秘匿が要件になったら macOS Keychain（`safeStorage` API）へ移す

### 優先度

P2

### ステータス

対処済み（周知のみ。保存方式の変更は要件が出たら）
