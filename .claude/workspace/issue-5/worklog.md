## 2026-07-28 - E2E をウィンドウ非表示既定にし、表示遷移が実行時間の大半だったことが分かる

### 実施内容

ローカルで E2E を回している間、Electron のウィンドウがマウスとキーボードを奪って他の作業ができない、という指摘を受けた対応。

- `make e2e` の既定をウィンドウ非表示に変更（環境変数は `AI_TERMINAL_E2E_HIDDEN` -> `AI_TERMINAL_E2E_SHOW` へ反転）
- `make e2e-headless` を廃止し、代わりに `make e2e-visible`（目で追いたいときだけ）を追加
- 隠し方を「起動後に `hide()`」から「`BrowserWindow.prototype.show` の無効化」に変更
- macOS では `app.dock.hide()` も呼ぶ
- `e2e/screenshots.spec.ts` は先頭で `AI_TERMINAL_E2E_SHOW=1` を立てて表示を強制

### 設計判断

- **「表示してから隠す」では要件を満たしていなかった。** 最初の実装は `firstWindow()` の後に `win.hide()` を呼んでいたが、それだと**一瞬ウィンドウが現れてフォーカスを奪う**。テストの本数だけ繰り返されるので、解決したかった問題がそのまま残っていた。`show()` を最初から無効化する形に変えた
- **macOS ではウィンドウを出さなくてもアプリがアクティブになる。** 起動そのものがアプリケーションをアクティブにし、編集中のエディタからキーボードフォーカスを奪う。`app.dock.hide()` でアクセサリ扱いにすると起きなくなる
- **アプリ本体は変更しない方針を維持した。** すべてハーネス側の `app.evaluate()` で完結している
- **撮影だけは表示を強制する。** 環境変数を Makefile ではなく spec の先頭に置いたのは、`npx playwright test --config=...` を直接叩かれても撮影が壊れないようにするため

### 教訓

- **「動いた」と「要件を満たした」は別。** 前のエントリで「全32シナリオが非表示で green」と書き、実測値（rAF 61fps・ピクセル一致）まで添えていたが、**ユーザーの困りごと（マウスを奪われる）はまったく解決していなかった**。検証していたのは「隠しても検証範囲が狭まらないか」であって、「実際にウィンドウが出ないか」ではない。**測る対象を、実装の都合ではなく元の困りごとから決めること**
- **原因の見立てを、直す前に測って否定する。** 非表示だと1テストあたり +4.6 秒かかることに気づき、Chromium のバックグラウンド throttling を疑って `webPreferences.backgroundThrottling: false` をアプリに入れた。**測り直したら差はまったく無かった**（原因は表示遷移そのもの）。実測に基づかない変更だったので取り消した。アプリの挙動を変える前に、仮説を否定できるか測ること
- **副次的に、フル実行が約3分から27秒になった。** 表示遷移のコストが実行時間の大半を占めていた。ウィンドウを出さない方が「速い」というのは事前には予想していなかった

### 次に再開するとき最初に読むべきこと

1. ブランチは `feat/memo-notify-settings-dev-loop`、PR は [#6](https://github.com/Yoshinaga-iwnl/ai-terminal/pull/6)
2. 検証の状態: `make check` green、**`make e2e` 32/32 green・flaky 0・27.2 秒**、`make e2e-lint` FAIL=0 WARN=0、`lint-skills` FAIL=0、`make e2e-screenshots` 12/12

## 2026-07-28 - 「撮影には表示が要る」という結論が誤りだったので撤回した

### 実施内容

前エントリで「Playwright の `page.screenshot()` は非表示ウィンドウではタイムアウトするので、撮影だけは表示を強制する」と結論づけていた。裏取りの指示を受けて調べ直した結果、**この結論は誤りだった**ので撤回した。

- `e2e/screenshots.spec.ts` の `AI_TERMINAL_E2E_SHOW = '1'` を削除
- `make e2e-screenshots` も非表示のまま動くようにした（12枚とも表示時と同じ内容）
- ハーネス・`/e2e` skill・README・Makefile の記述を訂正

### 何が誤りだったか

タイムアウトを観測したのは事実だが、それは**「表示してから `hide()` した」方式のとき**だった。原因を「非表示だから」と取り違えたまま、`show()` を最初から無効化する方式に変えた後も再検証せずに例外を残していた。

同じ「ウィンドウが見えない」状態でも、Chromium の扱いが違う:

| 隠し方 | `page.screenshot()` |
|---|---|
| 表示してから `hide()` | 30 秒でタイムアウト |
| `show()` を最初から無効化 | 89ms で成功。画像も表示時と同じ |

Chromium は表示済みのウィンドウが隠れると occluded 扱いにして合成を止めるが、一度も表示していないウィンドウはその遷移を経ない、と理解している。

### 裏取りの経緯

1. Web 検索で機序の裏を取った。Chromium は背面・occluded なウィンドウの Renderer を落とすこと、テスト用途では `--disable-backgrounding-occluded-windows` / `--disable-renderer-backgrounding` / `--disable-background-timer-throttling` を付けるのが定石であること、Electron の `capturePage()` にも occluded なウィンドウで空画像を返すバグ（#31992、Windows 限定・修正済み）があることを確認
2. **フラグで解決できる可能性が出てきたので、実測に戻した。** 現在の実装（`show()` 無効化）でそのまま `page.screenshot()` を叩いたところ、フラグ無しで 89ms で成功した
3. 撮影スイート全体（12枚）を非表示で3回走らせ、コミット済みの画像（表示時に撮ったもの）と内容が一致することを目視で確認した

### 教訓

- **原因を取り違えたまま作った例外は、原因が消えても残る。** 「表示してから隠す」をやめた時点で撮影の前提も変わっていたのに、例外だけがそのまま残っていた。**実装方式を変えたら、その方式を前提に作った回避策を全部見直すこと**
- **検索は機序の裏取りには効くが、結論の代わりにはならない。** 今回、検索結果は「非表示だと描画が止まる」という筋書きを支持していた（つまり誤った結論を補強する方向に働いた）。決着がついたのは、フラグの話をきっかけに実測へ戻したから。**裏取りで自分の結論が補強されたときこそ、測り直す**
- **画像は開いて見る。** 比較の過程で、S22 の README 画像に変換中の文字列が写っていないことに気づいた（`known-issues.md` の 4 番）。これは今回の変更とは無関係の既存の問題で、テストは緑のまま見逃されていた

### 次に再開するとき最初に読むべきこと

1. ブランチは `feat/memo-notify-settings-dev-loop`、PR は [#6](https://github.com/Yoshinaga-iwnl/ai-terminal/pull/6)
2. 検証の状態: `make check` green、`make e2e` 32/32・26.6 秒、`make e2e-screenshots` 12/12・10.4 秒、`make e2e-lint` FAIL=0 WARN=0、`lint-skills` FAIL=0

### 設計判断

- **CLI 側を先に実機で確認した。** `claude agents --help` は `--cwd` を "Show only background sessions started under `<path>`" と説明しており、対話セッションには効かない可能性があった。実機（v2.1.220）で叩いたところ `kind: "interactive"` にも効き、無関係なパスでは `[]` が返った。**アプリ側を疑う前に、前提が成立しているかを確かめた**（成立していなければ直し方がまるで変わる）
- **偽 CLI に `--cwd` を実装した。** これが無いと、絞り込みが完全に壊れていてもテストは緑になる。**偽物が本物を真似ていない部分は、そのまま検証の穴になる**
- **node を PATH に足さず、絶対パスを環境変数で渡した。** 偽 CLI で JSON を絞るのに node が要るが、PATH は「本物の claude / gemini を拾わない」ために `/usr/bin:/bin:/usr/sbin:/sbin` へ絞ってある。node のディレクトリを足すと、そこに本物の CLI が同居していたときに隔離が崩れる
- **`/usr/bin/python3` を使わなかった。** PATH 上にあり json も使えるが、Xcode CLT が未導入のマシンでは実行時に導入プロンプトが出る。E2E の途中でそれが起きるのは避けた

### 教訓

- **設定項目は「保存できる」と「効く」が別。** チェックボックスは動き、`config.json` にも書かれ、Main も読んでいた。**繋がっていなかったのは Renderer -> Main へ渡す引数1つだけ**で、経路のどこにもエラーが出ない。UI とファイルだけ見ていると正常に見える
- **`{}` を渡すのは、渡し忘れと区別が付かない。** `list({})` は型エラーにならない（`cwd?: string`）。optional なフィールドは「渡さない」が正常系にも異常系にもなりうるので、**型では守れない**
- **修正が二重になったら、テストがどちらを固定しているか確かめる。** `TaskList` と `poller` の変更は**どちらか一方だけでも直る**。片方ずつ戻して確認したところ S34 は両方戻したときしか赤くならなかった。テストが固定しているのは振る舞いであって実装ではないので、**将来どちらかが「使われていないコード」に見えて消される**危険がある。`/ai-cli` skill にその旨を書いた
- **偽物を疑うのが遅れた。** アプリを直した後もテストが赤で、原因は偽 CLI が `--cwd` を無視していたこと、さらにその修正が PATH に node が無くて動いていなかったこと。**ハーネスは検証対象ではないという前提が、ハーネスの不具合を見えにくくする**
