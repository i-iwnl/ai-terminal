### 0-4. 案の前提そのものを壊した指摘（a11y、単独だが致命的）

**`visibility: hidden` はアクセシビリティツリーからも部分木を除去している。**

初版は `visibility: hidden` を「`ResizeObserver` / `fit()` が壊れるから維持する」とだけ書いたが、副作用の半分しか見ていなかった。xterm の `AccessibilityManager` は `screenReaderMode` 有効時に **`aria-live="assertive"` の live region** を生成する（`node_modules/@xterm/xterm/lib/xterm.js`）。今は非表示タブが a11y ツリーから消えるので、**露出している live region は常に1個**という不変条件が偶然成立している。

**分割はこの偶然の遮断を無効化する。** 同一タブ内の全ペインが visible になり、assertive な live region が N 個同時に露出する。assertive は読み上げを**割り込んで中断する**ので、2ペインで claude と gemini を並走させた瞬間、VoiceOver は文を最後まで喋れなくなり、**ユーザー自身のタイピングのエコーすら潰れる**。

これは「分割の a11y 論点」ではなく、**分割がこのアプリの目的（エージェントの並走）と支援技術を正面衝突させる**話。

## 1. 矛盾した指摘と、どちらを採ったか

| 論点 | 対立 | 採った結論と理由 |
|---|---|---|
| 非アクティブペインの減光 | ヘビーユーザー「12〜15%減光すべき。**現行最大のアクセント（サイドバー下線 174px²）の 10.7倍の面積の青を、視野の中心に8時間点灯させる**」 vs 他4人「薄くしない（出力を読むために分割している）」 | **減光しない（4:1）。** ただし面積の指摘は数値として正しいので、**線を 2px -> 1px に落として吸収する**。ヘビーユーザー自身が「カーソルとクリックフォーカスを担保すれば 1px で十分」と書いており、両立する |
| スプリッタのキーボード到達 | IA「`role="separator"` + `tabindex="0"`」 vs macOS / a11y / ヘビーユーザー「**Tab は xterm が端末入力として食うので到達不能**。ARIA で嘘をつくな」 | **`tabindex` を付けない（3:1）。** `role="separator"` + `aria-label` + `aria-valuetext` は残し、**メニュー項目とショートカットからプログラム的に `focus()` する**。これが 2.1.1 を満たす唯一の経路であることを明記する |
| `Cmd+Shift+W` の新設 | macOS「単一ウィンドウなので衝突しない、賛成」 vs ヘビーユーザー「**macOS 全域で `Cmd+Shift+W` は『ウィンドウを閉じる』**。そこに『N 本の PTY を確認なしで kill』を割り当てるのは破壊的な逆マッピング」 | **新設しない（ヘビーユーザーを採る）。** 衝突しなくても、そう学習している指が N 本のエージェントを殺す。被害が非対称。`menu.ts:32-47` の `actionItem` は `accelerator: undefined` を受けられるので、**キー無しのメニュー項目**にする |
| 細すぎるペインの扱い | macOS / a11y / IA「拒否せよ」 vs ヘビーユーザー「**最小ウィンドウでも左右2分割で23桁残る。拒否のコードパスを書く価値がない**」 | **桁数で判定して拒否する（3:1）。** ただし両者の計算は矛盾しない -- ヘビーユーザーは fontSize 13px 固定、a11y は 26px で12桁。**閾値を「実セル幅 x 20桁」で持てば、fontSize を上げた人だけが拒否に当たる**。これが両方成立する唯一の書き方 |

**全員一致の対案をそのまま実装しなかった箇所:** 5人中4人が「スプリッタは `--border-control` #7a7a7a（対 `--surface-1` で 3.77〜3.88）にせよ」と書いたが、**a11y だけが、その結果アクティブ線 `--accent` #5b9cff との比が 1.56 になって隣接時に識別できなくなることを計算していた**。しかも `#1e1e1e` に対して 3:1 かつ `#5b9cff` に対して 3:1 を同時に満たすグレーは 256段の中に1つも存在しない。したがって `--border-control` を採ったうえで、**`prefers-contrast: more` のときアクティブ線を `--focus-ring` #ffffff に切り替える**（対 #7a7a7a で 4.29）。多数決の結論は採り、その結論が壊す別の数値をこちらで補った。

**このドキュメント中のコントラスト値は、すべて S40 に行を追加して実測で確定させる。** 紙の上の表は、このリポジトリで3回続けて誤っている（`design-rules.md`）。

## 2. 改訂した提案

### 提案 A'（改訂）: 二分木 + PTY メタは leaf に持つ

```ts
type PaneLeaf = {
  kind: 'leaf'; paneId: string;
  ptyId: string; ptyKind: PtyKind; title: string;
  agentSessionId?: string; cwd?: string;
  exit?: { exitCode: number; signal?: number };
};
type PaneNode = PaneLeaf | { kind: 'split'; dir: 'row' | 'column'; children: [PaneNode, PaneNode]; ratio: number };
```

- `TabState` に残るのは `id` / `layout` / `activePaneId` / `createdAt` だけ
- **`PaneNode` を `src/shared/` に置かない。** Main はペインの木を知る必要がない（PTY の spawn/kill は既存 API のまま）。鉄則3の対象範囲を Renderer のレイアウト都合で膨らませない
- タブの終了バッジ（`TabBar.tsx:77,122`）は**全 leaf が終了したときだけ**出す
- `ratio` は state ツリーに入れず、**ref + inline style** で持つ（state に入れるとドラッグのたびに `canFocusTaskTab` が再生成され `TaskList` が再レンダリングされる）

### 提案 B'（改訂）: キーとメニューは同じ PR

| 操作 | キー | メニュー |
|---|---|---|
| 右に分割 | `Cmd+D` | **ファイル > 新しいシェルタブ の直下** |
| 下に分割 | `Cmd+Shift+D` | 同上 |
| ペインを閉じる | `Cmd+W`（意味変更） | ファイル |
| タブを閉じる | **キー無し** | ファイル（`タブを閉じる（N ペイン）`） |
| 次 / 前のペイン | **`Cmd+]` / `Cmd+[`** を第一に。`Cmd+Option+矢印` を併設 | 表示（4方向 = **4項目**） |

- 置き場を「表示」から**「ファイル」**へ（IA）。分割は「新しいターミナルを作る」操作で、「表示」は倍率とフルスクリーンの棚
- 「次のペイン」1項目に4方向のキーは載らない（メニューの accelerator は1項目1つ）。**4項目に分ける**
- `Cmd+]` / `Cmd+[` を第一にするのは、**`Cmd+Option+矢印` がガード改修（U1）に依存するのに対し、これは依存しない**から。2ペインでは「どっちの方向か」の判断も消える（40〜80回/日で最も効く）
- **ラベルは「垂直分割 / 水平分割」にしない。** iTerm2 の Split Vertically は「左右に並ぶ」の意味で、日本語話者の半数が逆に読む
- **タブバー右端（設定の左）に文字ボタン `分割`** を置く。マウスだけの人の唯一の導線。タブバーは既に 36px 出ているので原則3（横幅の既定 0px）は破らない

### 提案 C'（改訂）: アクティブペインの表現は3層

1. **xterm の非フォーカス時カーソル（中空・非点滅）が第一の手がかり。** 追加コスト0、色に依存しない形の差、ペイン内部にあるので拡大しても視野に残る。**アクティブペイン以外を `focus()` しない**ことだけが実装要件
2. **アクセント線 1px**（2px から縮小）。**`box-shadow: inset 0 1px 0 var(--accent)` で描く。`border` は禁止**（Q2）。`.terminal-pane` の padding 帯（`--surface-1` #1e1e1e 上、6.07）に置く -- **canvas の上に置くと、白系テーマで 2.75 に落ちて 1.4.11 を割る**。`inset` にするのは、非 inset だと `.terminal-stack { overflow: hidden }` で外周ペインの端が切られるため
3. **語**: ペインヘッダ（下記 提案 G）

`prefers-contrast: more` のときはアクセント線を `--focus-ring` #ffffff に切り替える（`styles.css:174-182` に1行）。

**非アクティブ側に薄い線を描かない。** 描いた瞬間、`design-rules.md` で却下済みの「位置が同じで色だけ違う」形に落ちる。

### 提案 D'（改訂）: スプリッタ

- **色は `--border-control` #7a7a7a**（`--border-subtle` の 1.13 は不可視）。新しいトークンを作らない
- 表示 1px / 当たり判定 8px（`::before` の絶対配置）。**フォーカスリングは 8px の当たり判定ボックス側に `outline-offset: 0` で描く**（1px のボックスに `outline-offset: -2px` は退化する）
- `role="separator"` + `aria-label="左右の分割比"` + `aria-valuenow/min/max` + `aria-valuetext="左 60% 右 40%"`。**`tabindex` は付けない**
- **`aria-orientation` は分割線自身の向き。** 左右分割（`dir: 'row'`）のスプリッタは縦線なので `vertical`。**`dir` をそのまま渡すと確実に逆になる**
- **WCAG 2.5.7（ドラッグ動作、2.2 の AA）と 2.5.8（ターゲットサイズ 24x24）を、メニュー項目1組で同時に満たす**: 「分割比を広げる / 狭める / 50% に戻す」。8px は 2.5.8 の 33% しかなく Spacing 例外も使えない（隣接ペインと 0px 間隔で交差する）が、**Equivalent 例外の根拠がこのメニュー項目**になる。24px に広げる案は却下（各ペインの端 1.5桁が xterm の選択から死ぬ）
- **ドラッグ中は Grid を動かさず、絶対配置のゴースト線だけを動かして `mouseup` で確定する。** 初版の「`fit()` を呼ばない」は**自分の手で呼ばないという意味しか持たず、`ResizeObserver` は止まらない**。ゴースト方式なら `useTerminal.ts` を1行も触らずに済む
- ペインの端 8px がクリックのデッドゾーンになるので、**移動量が閾値未満の `mouseup` は「その側のペインをアクティブにする」**として扱う

### 提案 E'（改訂）: 閉じる

- 木を平らに畳む（初版どおり）
- **閉じるペインの子孫にある全 leaf の PTY を kill する。** `useTabs.ts:117` は `tab.ptyId` を1本しか kill しないので、そのままだと3ペインのタブを閉じたとき **PTY が2本漏れて `claude` が裏で走り続ける**
- **2つ以上の PTY を一度に閉じるときは確認する。** 文言は「N 個のペインを閉じます」ではなく**「走行中のプロセス N 件を終了します」**（何が失われるかの語）
- **タブバーの x ボタン（`TabBar.tsx:126`）が抜け穴。** `Cmd+Shift+W` を作らなくてもマウス経路の危険は消えないので、`title` / `aria-label` にペイン数を出し、同じ確認を通す
- 結果を `role="status"` で告知する（`Cmd+W` が「ペインを閉じた」のか「タブごと閉じて新しいシェルが開いた」のかは、視覚以外に区別する手段が現状ゼロ）

### 提案 F'（改訂）: cwd

- `newShellTab()` は現状 `spawn('shell', 'zsh')` を引数なしで呼び `getSharedCwd()` に落ちる（`useTabs.ts:98,69`）。**分割で一番作るのはシェルペインなので、`newShellTab(opts?)` の新設が要る**（初版の「`newAgentTab` が既にやっている」は根拠として外れていた）
- 引き継ぐのは**タブ生成時の cwd** であって実 cwd ではない。分割の主用途が「エージェントの隣で `git` を打つ」なので、`claude` を `/repo/packages/app` で動かしていると新しいシェルは `/repo` に出る。**`known-issues.md` に書き、ペインヘッダに cwd の basename を出して気づけるようにする**
- **OSC 7 による実 cwd 追跡は非目標**（明記しないと実装中に必ず誘惑される）

### 提案 G（新規）: ペインヘッダ

**分割中のみ**、各ペインの上に高さ 18px のヘッダを出す。`zsh` / `claude` / `claude (再開)` + cwd の basename。1ペインのときは出さない。

理由: IA が作った「分割の前後で意味が変わるもの」の表7行のうち**5行が『画面上の手がかり無し』**だった（`Cmd+K` / `Cmd+F` の宛先、ドロップ先、終了バッジ、タスク一覧クリック）。ヘッダを入れると4行が同時に埋まる。原則2「色は情報の補強であって情報そのものではない。**語を必ず併記**」に従う。

**幾何を分岐させない実装にすること**（1ペイン時と N ペイン時で `.terminal-pane__container` の内寸が変わると、その差分が SIGWINCH として実行中の子プロセスに届く）。

### 提案 H（新規・T1 の回収）: ドロップ可能領域のハイライト

ドラッグ中、カーソル下のペインに `box-shadow: inset 0 0 0 2px var(--accent)` の**4辺の枠**。アクティブ線（上辺1本）と**形で分ける** -- 同じ accent で辺だけ違うのは、却下済みの「位置が同じで色だけ違う」と同型。

- `dragleave` は子要素（xterm の canvas）に入るたびに発火するのでカウンタで管理し、`drop` でも必ず消す
- **合成 `DataTransfer` で `dragover` を投げれば E2E の関門になる**（S42 が既にその経路を使っている）。この周で唯一「新機能なのに機械で守れる見た目」

### 提案 I（新規）: ペインの最大化トグル

`Cmd+Shift+Enter`。初版は非目標にしていたが、**ドラッグ 2〜5回/日 に対し最大化 10〜30回/日**（ヘビーユーザーの実測）。既定 1200px の左右2分割は **58桁**で `git diff` も claude の unified diff も折り返すため、**58桁という予算では最大化が唯一の逃げ道**。ドラッグより先に置く。

**PR 3 が要。** 「木を入れるが振る舞いを1つも変えない PR」は、E2E の diff が0行であることがレビューの根拠になる。初版の周2はここに機能追加を混ぜていたので、分割が壊れたとき「モデル移行のバグか、分割の実装のバグか」を分離できなかった。CSS の「置換と値の変更を混ぜない」と同じ理屈。

## 4. 却下した提案と理由

| 案 | 出どころ | 却下理由 |
|---|---|---|
| `Cmd+Shift+W` でタブを閉じる | 初版 / macOS ペルソナが支持 | macOS 全域で「ウィンドウを閉じる」。衝突しなくても、そう学習している指が N 本のエージェントを殺す。**キー無しのメニュー項目**にする |
| 非アクティブペインを 12〜15% 減光する | ヘビーユーザー | 4人が反対。**出力を読むために分割している**ので目的と衝突する。面積の指摘（現行最大のアクセントの10.7倍）は正しいので、線を 2px -> 1px に落として吸収した |
| スプリッタに `tabindex="0"` | IA | Tab は xterm が端末入力として食うので**到達できない**。ARIA で到達可能を名乗るのは嘘。メニュー + ショートカットからプログラム的に `focus()` する |
| スプリッタを 24px に広げて 2.5.8 を満たす | （検討） | 各ペインの端 1.5桁ぶんが xterm のテキスト選択から死ぬ。原則3と衝突。**Equivalent 例外をメニュー項目で主張する**ほうが安い |
| 細すぎるペインの拒否は不要 | ヘビーユーザー | fontSize 13px 固定の計算。26px（200%拡大）では左右2分割で29桁、最小ウィンドウで12桁。**閾値を実セル幅 x 20桁で持てば両方成立する** |
| ペインごとに面を塗り分ける（`--surface-0` / `--surface-2`） | （検討） | `--surface-1` 固定方針と、`.terminal-pane__container` の padding による外周の帯の両方に抵触する |
| `prefers-reduced-transparency` / `prefers-reduced-motion` への対応 | （検討） | このアプリに半透明面は `--shadow-float` のみ、`transition` / `animation` / `@keyframes` は**実コード0件**。`design-rules.md` に「存在しない動きを止めようとしていた」として却下済み。**同じ轍を踏まない** |
| サイドバー 0px トグル（`Cmd+B`）をこの Issue に同梱 | ヘビーユーザー | 分割の桁数を 58 -> 75 に増やす効果は認めるが、**`issue-20/worklog.md` が既に「`Cmd+B` は別 Issue に切る」と決めている**。ここで蒸し返さない |

## 6. この案が積み残す、分割とは独立の負債（別 Issue 候補）

レビューで見つかったが、分割の実装とは独立に存在するもの。**分割の周に混ぜない。**

1. `TERM_PROGRAM` が素通しされ、新しいシェルタブのたびに `Restored session: ...` という**嘘の行**が出る（`manager.ts:109-118`。`docs/images/S01-launch.png` の1行目がそれ）。`env.TERM_PROGRAM = 'ai-terminal'` の1行で消える
2. **tmux の `-A` が既存セッションに当たる経路がコード上1本も存在しない**（`manager.ts:170` の名前は毎回 fresh な `randomUUID`）。`tmux.ts:3-6` のコメント「アプリ再起動後も `-A` で拾い直せる」は実現していない。`Cmd+W` は tmux クライアントを kill するだけなので **claude は生き続け、アプリからは二度と戻れない**
3. `Cmd+Shift+G`（macOS 全域で「前を検索」）が gemini 起動に取られている。**検索中に反射で押すと gemini が1本起動する**
4. `Cmd+G`（次を検索）が無い。現状は検索入力欄内の Enter だけ
5. `Cmd+1`〜`9` しかなく、**10枚目以降のタブにキーボードで到達できない**
6. `TaskList.tsx:85-95` の `<li onClick>` に `tabindex` も `role` も無い（キーボードで押せない）
7. `wrappedInTmux` が `useTabs.ts:80-88` で捨てられている
8. `.terminal-search` が細いペインからはみ出す（実測 260px 前後）
9. `e2e/screenshots.spec.ts:12` のコメントが「11シナリオ」（実際は12）
10. `App.tsx:106-116` のグローバル keydown が `e.target` を見ずに capture で先取りするので、**タブ名の編集中に `Cmd+D` を押すと分割が走る**
