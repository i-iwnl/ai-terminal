## 3. 提案 F' の cwd は、分割の主用途で実際に外れる -> #93 として起票済み

### 症状

引き継ぐのは**タブ生成時の cwd** であって実 cwd ではない。
`claude` を `/repo/packages/app` で動かしていて分割すると、新しいシェルは `/repo` に出る。

### 原因

~~シェルの実カレントディレクトリを追跡していない（OSC 7 未対応）。~~

**この前提は #58（PR #72）で覆った。** `src/main/pty/cwd.ts` が `lsof -a -d cwd -p <pid>` で
OS にプロセスの cwd を聞き、`useTabs.ts` が 2 秒間隔でポーリングしてシェルタブの `cd` に
追従する。OSC 7 は今も未対応だが、**追跡そのものは実装されている**。

残る本当の問題は次の2つに絞られる。

1. **エージェントタブ（claude / gemini）は追跡対象外**（`useTabs.ts` の
   `CWD_POLL_INTERVAL_MS` のコメント参照。「自分から cd しない」ため意図的に除外）。
   claude が内部で作業ディレクトリを変えても画面には出ない
2. **tmux でラップしている場合、`lsof` が返すのは tmux クライアント側の cwd** で、
   シェルの実際の作業ディレクトリとは無関係になる。**既定で tmux ラップが有効なので、
   これは例外ではなく通常経路**

### 影響範囲

分割の主用途がまさに「エージェントの隣で `git` を打つ」なので、**静かに間違ったディレクトリでコマンドを打たせる**。

### 対処方針

- [ ] ペインヘッダに cwd の basename を出して**気づけるようにする**（提案 G に含む）
- [ ] OSC 7 による実 cwd 追跡は**非目標**。必要になったら別 Issue

### 優先度

P3

### ステータス

**前提を訂正した（2026-07-30）。** 初出時の「実 cwd を追跡していない」は #58（PR #72）で
解消済み。残っているのは「エージェントタブが追跡対象外」と「tmux ラップ時に lsof が
別プロセスの cwd を返す」の2点で、**どちらも分割の主用途（エージェントの隣で git を打つ）に
直撃する**。緩和策（ペインヘッダに cwd の basename を出す）は提案 G のまま。

**起票時は、この訂正後の内容を書くこと。訂正前の「追跡していない」は誤り。**
