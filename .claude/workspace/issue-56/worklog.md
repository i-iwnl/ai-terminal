### 案の前提そのものを壊した指摘（a11y、単独だが致命的）

**`visibility: hidden` はアクセシビリティツリーからも部分木を除去している。**
初版はこれを「`ResizeObserver` が壊れるから維持する」とだけ書いたが、副作用の半分しか見ていなかった。
xterm は `screenReaderMode` 有効時に `aria-live="assertive"` の live region を作るので、
今は「露出している live region は常に1個」が**偶然**成立している。分割はこの遮断を無効化し、
assertive が N 個同時に露出する。**2ペインで claude と gemini を並走させると VoiceOver は文を最後まで喋れなくなり、
ユーザー自身のタイピングのエコーまで潰れる。**

### 矛盾した指摘と、どちらを採ったか

`design-review.md` の「1. 矛盾した指摘と、どちらを採ったか」が唯一の正。要点だけ:

- **非アクティブペインの減光**: 4対1で「減光しない」。ただし「現行最大のアクセントの10.7倍の面積の青を視野中心に8時間点灯させる」という指摘は数値として正しいので、**線を 2px -> 1px に落として吸収**した
- **`Cmd+Shift+W`**: macOS ペルソナは賛成、ヘビーユーザーは反対。**反対を採った**（macOS 全域で「ウィンドウを閉じる」。衝突しなくても、そう学習している指が N 本のエージェントを殺す。被害が非対称）
- **細すぎるペインの拒否**: 3対1で拒否。ただし両者の計算は矛盾しておらず、**閾値を「実セル幅 x 20桁」で持てば両方成立する**（13px では当たらず 26px では当たる）

### 設計判断

- **全員一致の対案をそのまま実装しなかった。** 5人中4人が「スプリッタを `--border-control` にせよ」と書いたが、
  a11y だけが「その結果 `--accent` との比が 1.56 になる」を計算していた。しかも
  **`#1e1e1e` と `#5b9cff` の両方に対して 3:1 を満たすグレーは 256段に1つも存在しない**。
  多数決の結論は採り、`prefers-contrast: more` でアクティブ線を `--focus-ring` に切り替えることで補った
- **周の切り方を 4周 -> 10 PR に組み替えた。** うち PR 0-a / 0-b / 0-c / 1 は
  「案の前の別作業」で、分割が1行も入らなくても単独で意味がある（3人以上が指摘した項目は
  案の中ではなく案の前に切り出す、という規約に従った）
- **PR 3（木を導入するが常に leaf 1枚。分割はできない）を新設した。**
  E2E の diff が0行であることがレビューの根拠になる。CSS の「置換と値の変更を混ぜない」と同じ理屈で、
  分割が壊れたとき「モデル移行のバグか、分割の実装のバグか」を分離できる

### 教訓

- **自分が直前に書いたドキュメントと、自分が書いた案が矛盾していた。** `architecture.md` に
  「fit は ResizeObserver が見ているので個別の呼び出しは要らない」と書いた3時間後に、
  案には「ドラッグ中は fit を呼ばない」と書いていた。**実装者は architecture.md を読み、ゲートを入れないほうを採る。**
  レビューが指摘するまで気づかなかった
- **「呼ばない」と「発火しない」は違う。** 提案 D の「ドラッグ中は `fit()` を呼ばない」は、
  自分の手で呼ばないという意味しか持たない。`ResizeObserver` は Grid の比率が変われば勝手に発火する
- **`design-rules.md` に書いてある規約を引用しても、適用を誤ることがある。**
  「装飾の線は 1.4.11 の対象外」は規約どおりだが、**スプリッタは装飾ではなくコントロール**だった。
  規約の引用は、その規約が当てはまるかの判断を代替しない
- **議題の引き継ぎが1周で落ちた。** Issue #55 の known-issues 3 と issue-56 の overview P1 の
  両方に「ドロップハイライトを design-review に載せる」と書いていたのに、案に1行も書かなかった。
  **書いた本人が忘れる**ので、案を書くときに前周の known-issues を開く手順が要る
