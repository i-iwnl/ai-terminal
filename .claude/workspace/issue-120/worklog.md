### 設計判断

- **`Cmd+E` を残した理由は「壊れ方の重さの違い」。** #62（`Cmd+Shift+G` が
  gemini 起動）は**本物のプロセスが1本余計に起動し、ユーザーが見つけて kill
  しなければならない**。`Cmd+E` はタブが切り替わるだけで、**トグルなので
  もう一度押せば戻る**（誤爆が自己修復する）。加えて代替の
  `Cmd+Shift+英数字` はどれも語呂が無く、**覚えられないキーは使われないので
  機能を残したことにならない**
- **zoom の `role` は残さず捨てた。** 残したまま同じキーに fontSize を足すと
  **同じキーが2系統から発火する**（#20 が「(a) を採るなら zoom をどうするかを
  同じ PR で決める」と条件を付けていた箇所）。「ターミナルの文字サイズを変える」の
  ほうが利用者の意図に近い
- **フォントサイズの連打は間引かない。** 1回のキー入力で1段階変わることが
  期待どおりの挙動で、デバウンスすると「押したのに変わらない」に見える。
  実際に飛ぶ `pty.resize` の回数は `resizeGate.ts` の `shouldSendResize`
  （cols/rows が変わった回だけ通す）が抑える

### 教訓

- **`MenuItem.role` は小文字で返る。** Electron は指定した綴りをそのまま返さず
  正規化する（`hideOthers` -> `hideothers`、`toggleDevTools` -> `toggledevtools`）。
  そのため **S36 の既存の検査 `not.toContain('forceReload')` と
  `not.toContain('toggleDevTools')` は一度も機能していなかった**
  （キャメルケースの文字列は決して一致しないので、実際にその role を足しても
  緑のまま通る）。効いていたのは元から小文字だった `'reload'` の1つだけ。
  **自分が足した zoom の検査も同じ罠にはまり、「壊したのに flaky 1件」という
  不自然な結果から気づいた**（決定的な assert が retry で通るのはおかしい）
- **P1 の周5 と同じ型の空振りを、2回目で見つけられた。** あちらは
  `if (取れたら) 検査する`、こちらは「文字列の綴りが実装と違う」。
  どちらも**「壊して赤くなるか」を実際にやらなければ発見できなかった**
- 既存の characterization 2件（`割り当ての無い Cmd+Alt+英字` の例に `KeyW` を
  使っていた / `Cmd+0` が null）が、変更を正しく捕まえた
