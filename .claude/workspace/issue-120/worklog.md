### 設計判断

- **`Cmd+E` を残した理由は「壊れ方の重さの違い」。** #62（`Cmd+Shift+G` が

  緑のまま通る）。効いていたのは元から小文字だった `'reload'` の1つだけ。
  **自分が足した zoom の検査も同じ罠にはまり、「壊したのに flaky 1件」という
  不自然な結果から気づいた**（決定的な assert が retry で通るのはおかしい）
- **P1 の周5 と同じ型の空振りを、2回目で見つけられた。** あちらは
  `if (取れたら) 検査する`、こちらは「文字列の綴りが実装と違う」。
  どちらも**「壊して赤くなるか」を実際にやらなければ発見できなかった**
- 既存の characterization 2件（`割り当ての無い Cmd+Alt+英字` の例に `KeyW` を

- **`Cmd+Shift+1/2/3` は使わない。** `Cmd+Shift+3` / `4` / `5` は macOS の

  **3番目で必ず破綻する**（旧 #111 が明示的に警告していた）
- **`Cmd+Option+` に寄せた。** 既に `Cmd+Option+S`（サイドバーの表示切替）と
  `Cmd+Option+W`（周1 で追加）があるので「Option+Cmd はサイドバー / ウィンドウ系」で

  送り返す配線（`menu:pane-count` と同型）が要るが、**どのパネルを見ているかは
  画面で直接確認できる**（セグメンテッドコントロールが選択中を示す）。
  すぐ上の「サイドバーの表示を切り替え」でラベルを状態に応じて変えないと決めたのと同じ判断
- **パネルの状態は Sidebar が持ったまま。** App へ持ち上げると、畳むたびに
  タブ選択・メモの編集途中・履歴の絞り込みが失われる。App は
  `registerPanelSwitcher` で「切り替えたい」を伝える口だけ持つ
- **`<button>` 要素そのものは変えない。** `e2e/` の 28 ファイル・44 箇所が
  `.sidebar__tabs button` を使う。`role` を**足す**のは問題ない

### 教訓

- **roving tabindex を「正しく」しておく意味は、到達できなくてもある。**
  Tab では実際に到達できない（xterm が Tab を食う）が、停止点の数を偽ると
  ARIA が嘘をつく。到達手段は `Cmd+Option+1/2/3` とメニューが担い、
  ARIA は構造の正しさだけを担保する、と役割を分けた
- **`Cmd+Option+数字` も `e.code` が要る。** Option+1 の `e.key` は `¡`。
  英字キー（`Cmd+Option+S` / `W`）と同じ罠が数字にもある

## 2026-08-03 - 周2 の統合検証で、自分の変更が他の spec を落とした

### 症状

`make e2e` のフル実行で **S57（ペインヘッダ）が落ちた。** flaky ではなく確実に落ちる。

```
Locator:  locator('[role="tabpanel"]')
Expected: 1
Received: 2
```

### 原因

**周2 でサイドバーに `role="tabpanel"` を足したため。**

S57 は「木のルートでない leaf は `role="tabpanel"` を名乗らない」という PR 4 の
契約を守る assert だが、**セレクタが文書全体**（`[role="tabpanel"]`）だった。
当時このアプリのタブ widget は1つ（タブバー）しか無かったので、それで足りていた。

**このアプリには独立したタブ widget が2つになった**ので、数える範囲を
`<main>`（タブバー + ターミナル）に絞った。

### 教訓

- **design-rules の「自分が触っていないファイルの spec が落ちる」の別形。**
  あちらは「密度を変えるとクリック位置が動く」だったが、こちらは
  **「ARIA のロールを足すと、文書全体を数えている assert が落ちる」**。
  どちらも「自分の変更が他人のテストを落とす経路」を想定していないと帰属を誤る
- **`.sidebar__content` から `role="tabpanel"` を外す、という直し方は採らなかった。**
  サイドバーの `role="tab"` は `aria-controls` でこの要素を指しているので、
  外すと**リンク先が tabpanel でなくなる**（S51 が同じ形の「リンク切れ」を
  タブバー側で防いでいる）。落ちた側のセレクタを絞るのが正しい
- **周ごとに名指しで spec を回すだけでは足りなかった。** 周2 では
  S36 / S40 / S44 / S72 / S75 を選んで回して全部 green だったが、
  S57 は「サイドバーを触ったら影響しそう」という見当に入っていなかった。
  **`role` のような文書全体に効く属性を足す周は、フル実行を待たずに
  `grep -rn 'role=' e2e/` で当たりを付けるべきだった**

### S61 の失敗は既知 flake だった

同じフル実行で S61（ペイン間移動）も落ちたが、**単独実行 3/3 で通り、
フル実行を回し直すと通った。** これは #120 の C-1（旧 #106）として登録済みの
「分割直後の `Cmd+]` が負荷下でのみ効かないことがある」で、周2 の変更由来ではない。
**周4 で扱う。**

### 着手前に実測したら、Issue 本文の前提が2点ずれていた

**「PR #108 の手法が使えないか先に実測する」の答えは「もう適用済みだった」。**

### 実施内容

- `.tab-bar__close` の `left` を広げるぶんだけ戻し、同じ量を `padding-left` に足した
  （`- (var(--target-size-min) - 14px)` / `+ (var(--target-size-min) - 14px)`）
- `S44-target-size.spec.ts` に「当たり判定がタブ選択の側（右）へ 1px も食い込まない」を
  `elementFromPoint` の 1px 刻みで追加。`hitsJustInside` も同時に見る
- `e2e/scenarios.yml` の S44 の note を追記
- `design-rules.md` に「当たり判定を広げるときは、広げた先が誰のクリック対象かを向きごとに見る」
- B-2 / B-3 の結論を #120 にコメントで書き戻した

### 設計判断

- **3案（縦だけ広げる / 高さを上げる / 現状のまま許容）はどれも採らなかった。**
  - (a) 縦だけ: 横を 14px に戻すと 24x24 を割る。**2.5.8 の spacing 例外も成立しない**
    （隣接ターゲットとの offset が 24px 未満）
  - (b) 高さを上げる: **問題は横軸。** 縦は既に 11px 余っており、高さを上げても
    誤爆は 1px も減らない。クロームの画素を払って何も買えない
  - (c) 現状のまま: **0px の見た目変更で食い込みを 0 にできる**ので許容する理由が無い
- **`::before` をずらすのではなく、ボタンの箱そのものを非対称に広げた。**
  `::before` をずらすと「`::before` は要素の中心にある」という前提が崩れ、
  **S44 の `measureHitArea`（中心 ± サイズ/2 の四隅）が測る矩形を間違える**。
  箱を広げれば中央寄せのまま `max(100%, ...)` が箱と一致するので、既存の測り方が生きる
- **`left + width` が不変**なので "x" の描画位置も右端も動かない。
  **この不変性はグリフの実測幅に依らない**（`left` を d 減らして padding-left を d 増やすだけ）
- **上下のはみ出しは意図的に残した。** そこは「閉じるを狙って縦に外した」位置で、
  押した結果は狙いと一致する。害があるのは**隣のターゲットへ向かう向き**だけ
- **B-3 は e（改名しない）。** `TaskList.tsx` の `このフォルダの Claude` /
  `このマシン全体の Claude`、`HistoryList.tsx` の `{すべてのフォルダ|このフォルダ}の {Claude|Gemini}`
  を実コードで確認。I-4 の2つの懸念（「タスク」がサブエージェントと紛らわしい /
  ターミナルで「履歴」の第一想起はシェルのコマンド履歴）はスコープ行が担っている。
  **改名しないので「実フォントで幅を実測する」は不要になった**（幅が理由の却下ではない）

### 教訓

- **サイズの assert は、隣へ食い込む壊し方に対して一度も赤くならない。**
  S44 は 24x24 を測っていたが、**その 24x24 がどこへ伸びているかは見ていなかった**。
  「関門はあるか」を問うときは、**その関門が赤くなる壊し方を具体的に1つ言えるか**を見る
  （loop.md「測る対象そのものが違う」の形）
- **`:hover` で出し入れしても当たり判定の問題は解決しない。** CSS の `:hover` は
  クリックする時点で必ず true なので、**まさに問題になる瞬間に有効化されている**。
  PR #88 がこれで空振りしていた
- **「はみ出し」は量ではなく向きで評価する。** 左右 5px ずつという同じ量でも、
  片方は死角に乗るだけで無害、もう片方は破壊的な誤爆になる
- **壊して赤くなるかを実際にやった。** CSS を戻して再ビルド -> S44 が
  **retry でも決定的に赤**（食い込み 5px を検出）。周1 の教訓
  （決定的な assert が retry で通るのはおかしい）どおりの形で確認できた
- **`make css-substitution-check` が落ちたのは正しい。** 幾何を意図的に変えたため
  （CLAUDE.md「値を意図的に変えるときだけ落ちてよい」）。`make check` には含まれない

### 設計判断

- **こだまを捨ててよい理由は「情報がゼロだから」。** effect が `focus()` を呼ぶのは
  **そのペインが既に active だから**で、跳ね返る focus が運ぶ情報は
  「active なペインが active である」だけ。**情報を持たない信号が、情報を持つ信号
  （キー操作）に勝てる**のが不具合の本体
- **クリック・ドロップ由来の focus は通す。** 門番が閉じるのは `run()` の内側だけ。
  `onFocusCapture` の本来の目的（Cmd+F / Cmd+W を正しいペインへ向ける）は残る
- **真偽値ではなく深さカウンタ。** 入れ子で内側の `run()` を抜けた時点で門が開くと、
  外側のこだまが素通りする。呼び出し元は1箇所だが、
  **開きっぱなしより早すぎる開きのほうが見つけにくい**ので構造で防いだ
- **`focus()` の配送が将来非同期化したら、門番は黙って無効になる**（バグが戻るだけで、
  本物の focus を誤って捨てることはない）。安全側に倒れる設計
- **C-2 で自動 `--resume` はしない**（issue-24 で「副作用が大きい」として却下済み。
  通知を押しただけで新しい PTY が生えるのは行き過ぎ）。再開の導線は履歴パネル
- **C-2 の空振りは「他アプリ起動」限定ではない。** tmux 永続化でタブだけ閉じた場合と、
  アプリ再起動後（`ownedSessionIds` はプロセス内 Set）にも同じ経路に落ちる
