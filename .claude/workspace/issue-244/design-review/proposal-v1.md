# Issue #244 デザイン案（初版・レビュー前）

> **対象**: 「タブを閉じる」の意味を変えることに伴う、画面上の文言・状態表現・導線の変更。
> **Issue**: https://github.com/i-iwnl/ai-terminal/issues/244
> **この文書はレビューで覆ることを前提に書いている。** リポジトリにはまだ入れていない。

---

## 0. 3行で

1. 「タブを閉じる」= tmux セッションごと **AI を終了する** に変える（いまは生き残って累積する）。
2. 残したいときは**メニュー**「タブを閉じて AI を残す」で明示する（ショートカットは割り当てない）。
3. タスク一覧の行に、**押せる手がかり**と**終了の導線**を出し、押せない行には**理由**を出す。

## 1. 現状の診断（すべて 2026-08-09 に実コードで確認）

### 1-1. 累積の発生源

| 事実 | 根拠 |
|---|---|
| `useTmux: true` が出荷時の既定 | `src/shared/defaults.ts:60` |
| `pty.kill()` が殺すのは tmux **クライアント**だけ。サーバ側のセッションと内側の `claude`/`gemini` は生き残る | `.claude/skills/terminal/reference/pty-pitfalls.md`（2026-08-03 実測・tmux 3.7b） |
| Main 側に tmux セッションを**終了させるコードが1行も無い**（`kill-session` の呼び出しはリポジトリ全体で0件） | `src/main/pty/tmux.ts` / `tmuxSessions.ts` |
| 閉じる操作は全部 `IpcInvoke.ptyKill` → `entry.pty.kill()` + `disposeEntry()` に合流し、**`disposeEntry` は tmux に触らない** | `src/main/pty/manager.ts` |

実機で **7本**の `claude` が1〜2日前から入力待ちのまま生存していた（Issue 本文の `ps` 出力）。

### 1-2. 閉じた直後の告知が、これから**事実として誤りになる**

`closedTabAnnouncement()`（`src/renderer/src/tabs/closeTabCopy.ts`）は
「タブを閉じても AI は走り続けている」を告知している。**閉じたら終わるなら、この文はそのまま嘘になる。**

⚠ この告知は design-rules 節8 で「**視覚から隠れた live region だけに流れていた**」ことが
5人中4人に指摘され、`closedTabChannel()` で通知バナーへ降格させた経緯がある。
**今回はその判断の前提（「プロセスが生き残ったことは見えない」）ごと変わる。**

### 1-3. 確認ダイアログの2番目の条件が不要になる

`needsCloseConfirmation()` は (1) 2本以上を一度に閉じる (2) `persistentOrphaned > 0`（tmux で
ラップされたのに `agentSessionId` が無く、閉じると二度と拾えない）で確認を出す。
**閉じたら終わるなら (2) の事故は原理的に起きない。**

### 1-4. タスク一覧の行に、押せる手がかりが**語として1文字も出ていない**

| 事実 | 根拠 |
|---|---|
| 押せる行は `<button class="task-item__row">`、押せない行は `<div class="task-item__row">`。**modifier クラスは付けない**（CSS も `button.task-item__row` で分岐） | `src/renderer/src/sidebar/TaskList.tsx` の `renderTask()` |
| 押せることの視覚的な手がかりは **`cursor: pointer` とホバーの塗りだけ** | `styles.css`: `button.task-item__row:hover { background: var(--surface-2) }` |
| そのホバーのコントラストは **`--surface-2` #222222 対 `--surface-0` #141414 = 1.16** | `:root` の実値 |
| 「タブに戻す」という語は `taskRowActionLabel()` が返すが、**`aria-label` の中でしか使われていない** | `src/renderer/src/sidebar/taskRow.ts` |

実際に「タブに戻すボタンはどこにある」と聞かれ、答えが「行そのものです」になった（Issue 本文）。

### 1-5. 押せない行に理由が無い

`resolveTaskRowAction(task, hasOpenTab)` が `'none'` を返す行は `<div>` になり、
**`aria-label` も付かず**（`taskRowActionLabel('none')` は `undefined`）、視覚的な差分も無い。
「アプリの外から起動された」のか「アプリが tmux を見つけられていない」のかが区別できない。
後者は `listLiveAgentSessions()` が空を返して**全行が一斉に押せなくなる**障害だが、静かに縮退するだけ。

### 1-6. ⭐ 行に要素を足す前に読むべき実測（design-rules 節8）

- `.task-item__name` は **12文字を超える名前で「このアプリ」バッジを 99px 画面外へ押し出していた**
  （サイドバー既定 260px。修正済みだが、**フロー内に幅を足すのは同じ壊れ方をする**）
- **`docs/images/` の13枚のどれにもバッジが写っていない**ため、画素の関門が1つも掛かっていなかった

⛔ **「入るはず」で足すと、いちばん名前が長い行 = いちばんその情報が要る行でだけ消える。**

## 2. この案が従う設計原則

1. **ホットパスに確認を増やさない。** 閉じるのは1日に何十回もある操作（Issue 本文）。
2. **不可逆になった操作は、確認ではなく「事後の告知」で埋める**（design-rules 節6 の降格ルール）。
   ただし降格先は「目で見て分かるか」で決める（節8）。
3. **色は情報の補強であって情報そのものではない**（design-rules 原則2）。押せる/押せないを塗りの差だけで表さない。
4. **ターミナルが主役。** サイドバーの行に常時ピクセルを予約しない。
5. **却下済みの案を再提案しない**（design-rules 節5）。

## 3. 提案

### 提案 A: 「タブを閉じる」= AI を終了する

| | 現在 | 修正後 |
|---|---|---|
| `Cmd+W`（ペインを閉じる） | tmux クライアントだけ死ぬ。**中の AI は生き残る** | **tmux セッションごと終了** |
| `Cmd+Option+W`（タブを閉じる） | 同上 | **同上** |
| タブバーの x / 右クリック「閉じる」 | 同上 | **同上** |
| **アプリを終了する**（`before-quit`） | セッションは生き残る | **変更なし（生き残る）** |
| 分割の失敗ロールバック | クライアントのみ | **終了**（起動直後の使い捨て） |

⛔ **`pty:kill` の意味を一律で変えない。** `before-quit` の `disposePtyAll()` が同じ経路を通るため、
「終了するか」は**呼び出し側が渡す**。

### 提案 B: 「タブを閉じて AI を残す」はメニュー項目のみ

```
ファイル
  新しいタブ                Cmd+T
  ─────────────────────────────
  ペインを閉じる             Cmd+W
  タブを閉じる（2 ペイン）    Cmd+Option+W
  タブを閉じて AI を残す
```

- ⛔ **`Cmd+Shift+W` は使わない。** `shortcuts.ts` と `menu.ts` の**両方**に
  「macOS 全域で『ウィンドウを閉じる』と学習されているので使わない」という明文の決定がある。
  `Cmd+Option+Shift+W` も `matchShortcut()` で明示的に不使用。
- めったに使わない操作なのでメニューで足り、`Cmd+Option+W` の隣に置けば発見可能性も確保できる。

**Q（レビューで判断してほしい）**: この項目は常時出すか、AI ペインを含むタブのときだけ有効にするか。
シェルタブでは tmux ラップされていないので**意味が無い**（無効化 or 非表示）。

### 提案 C: 閉じた直後の告知を書き換える

`closedTabAnnouncement()` の文言を、「走り続けている」から「終了した」に反転させる。

降格先の判定（design-rules 節8 の表）:

| 問い | この操作での答え |
|---|---|
| 目で見て分かることか | **タブが消えたのは見れば分かる** |
| 目で見ても分からないことか | **AI が終了したことは見えない**（が、それは**利用者が意図した結果**） |

**初版の判断**: 通常の「閉じる」では**何も告知しない**（意図どおりの結果に事後報告は要らない）。
「**閉じて AI を残す**」を選んだときだけ、**残った**ことを告知する（こちらは目で見て分からない）。

⚠ これは節8 の判断を**裏返す**ことになる。**レビューで検算してほしい最重要点。**

### 提案 D: 確認ダイアログは「2枚以上」だけ残す

`needsCloseConfirmation()` から `persistentOrphaned > 0` の条件を外す。文言も、
「生き残る」前提で書かれている箇所を「終了する」に直す。

### 提案 E: タスク一覧の行に、押せる手がかりと終了の導線を出す

`.task-item__row` は `<button>` **そのもの**なので、**中にボタンを入れ子にできない**（HTML 的に不正）。
前例は履歴側に既にある: `.history-item__row`（`<button>`）と `.history-item__actions` を
`.history-item__content` の**兄弟**にし、`__actions` を **absolute 配置**（`opacity` + `pointer-events` を
入れ物側に持たせ `:hover / :focus-within` で出す）。理由は styles.css のコメントに
「**フレックス行に置くと 96px が常時予約される**」という実測。

初版案:

```
┌─────────────────────────────────────────┐
│ ● あなたの番  demo-project    [戻す][終了] │  ← ホバー/フォーカス時のみ表示
│   実行許可待ち · demo-project · 2時間30分   │
└─────────────────────────────────────────┘
```

- 常時は隠す（原則4「常時ピクセルを予約しない」）
- **ターゲットサイズ 24x24 CSS px**（WCAG 2.5.8）を透明な当たり判定で確保する
- **終了は不可逆**なので、ここだけは確認を出す（ホットパスではない）

**Q（レビューで判断してほしい）**:
1. 「押せることが**見える**手がかり」を、ホバー時のみ出るボタンで満たしたと言えるか。
   **ホバーしていない静止画の状態では、いまと1ピクセルも変わらない。**
2. 行の残り幅は足りるか（`.task-item__name` の実測は「247px の右端」。1-6 の実測を参照）。
3. 語は「戻す」「終了」でよいか。⛔ 「**強制終了**」は Issue #166 で5人全員が却下済み。
   ⛔ 「実行中」「待機中」も禁止語（design-rules 節2）。

### 提案 F: 押せない行に理由を出す

`resolveTaskRowAction()` が `'none'` を返す理由を**種類ごとに言い分ける**:

| 理由 | 出す語（初版） |
|---|---|
| tmux セッションが見つからない（アプリの外から起動された） | このアプリからは操作できません |
| tmux が使えない / 一覧が取れない（**全行が一斉に押せなくなる障害**） | tmux が見つからないため操作できません |

⛔ 押せない行は `<div>` なので `aria-label` が無い。**視覚と読み上げの両方に届ける**必要がある
（S106 が同型の失敗を捕まえている）。

**Q**: 全行が一斉に押せなくなる障害は、**行ごとに書く**より**パネル単位のメッセージ**（`.panel-message`）が
適切ではないか。行ごとだと同じ文が10行並ぶ。

## 5. 非目標（この案でやらないこと）

- **tmux 永続化そのものの削除。** Issue 側で 2026-08-09 に実測済み（生きたセッションが 36〜39行の
  画面を保持 / 一覧の11件中10件が正しく解決）。`docs/PLAN.md:143` の動機は**アプリ終了**の話であって
  タブを閉じる話ではない。ここを消すと汎用ターミナルとの差別化がそのまま消える
- **`useTmux` の既定値の変更**（`true` のまま。害が出なくなるので議論が要らなくなる）
- **設定項目の追加**（「閉じたら終了するか」を設定にしない。**意味が2通りある操作は説明できない**）
- **アプリ終了時の挙動の変更**（生き残る、を維持する）
- **`e2e/fixtures/harness.ts` の既定フィクスチャの変更**（E2E 7箇所 + README 画像8枚が動く）

## 6. レビューで特に検算してほしい点

1. **提案 C**: 「意図どおりの結果には事後報告が要らない」は、design-rules 節8 の判断（降格先を
   視覚面に出す）を裏返している。**支援技術利用者が一方的に情報を失う形になっていないか。**
2. **提案 E**: ホバー時のみ出るボタンが、完了条件「押せることが**見える**手がかり（ホバーとカーソル以外）」を
   満たすと言えるか。⛔ design-review の `implementation-traps.md` に `opacity: 0` の罠がある。
3. **提案 E**: 260px のサイドバーで、行の右端に24px のボタン2つを置く余地が本当にあるか（**実測で**）。
4. **提案 B**: シェルタブで「タブを閉じて AI を残す」をどう扱うか（無効化 / 非表示 / 常時有効）。
5. **提案 F**: 「全行が一斉に押せない」障害を、行単位で書くかパネル単位で書くか。
6. **提案 A の抜け**: 「終了する」と決めた結果、**閉じたあとに気が変わっても戻せない**。
   Issue が挙げた「1日に何十回」のホットパスで、**取り消し（Undo）が要るか**。
