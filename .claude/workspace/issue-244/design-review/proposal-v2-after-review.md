## 2. 改訂した提案

### 提案 A'（閉じる = 終了）— 採用。ただし Contract を確定させる

**チャンネルは2本要る。**

| 用途 | チャンネル | 引数 | tmux 名の解決者 |
|---|---|---|---|
| タブ/ペインを閉じて終了 | `IpcInvoke.ptyKill`（**ALTER**） | `{ ptyId, terminateSession?: boolean }` | **Main**（`PtyEntry.tmuxSessionName`） |
| 一覧の行から終了（タブが開いていない） | **新設** `IpcInvoke.agentSessionKill` | `agentSessionId: string` | **Main**（`buildTmuxSessionName`） |

⭐ **2本目が要る理由**: `resolveTaskRowAction` が `'recover'` を返すのは `hasOpenTab === false` のときだけ。
**その行には ptyId が存在しない**（Main に entry が無い）。

⛔ **Renderer に `aiterm-` を組み立てさせない。** 接頭辞の正は `buildTmuxSessionName`（付ける）と
`SESSION_NAME_PREFIX`（剥がす）の2箇所だけ。3箇所目を作ると `tmux.ts` 冒頭が「唯一の正」と
宣言している非対称の説明が、また片方だけ腐る（「実際に一度そうなった」と書いてある）。

⭐ **`PtyEntry` に `tmuxSessionName` を持たせる**（`entries.set` の時点）。名前は
`maybeWrapWithTmux` の中で**既に確定している**ので、戻り値に足すだけ。
**これは D の可否にも直結する**（下 §3）。

**`before-quit` は1行も触らない**（`disposePtyAll()` は IPC ハンドラを通らないので自動的に据え置き）。

### 提案 B'（メニュー項目）— 採用。文言と有効/無効を確定

```
ファイル
  新しいシェルタブ            Cmd+T
  右に分割                   Cmd+D
  下に分割                   Cmd+Shift+D
  新しい Claude タブ          Cmd+Shift+C
  新しい Gemini タブ          Cmd+Shift+E
  ──────────────────────────────────
  ペインを閉じる              Cmd+W
  タブを閉じる（2 ペイン）     Cmd+Option+W
  AI を残してタブを閉じる                    ← 新設・ショートカット無し
```

- **文言は `AI を残してタブを閉じる`。** IA の指摘: 直前の項目と**先頭6文字が同じ**だと、
  メニューは左から走査するので差分が語尾に隠れる。**差分を先頭に出す**
- **シェルタブでは `enabled: false`**（4/4 一致）。判定は `summarizeClosingPanes(leaves).persistentResumable + persistentOrphaned > 0`。
  配線は `IpcSend.menuPaneCount` → `updateCloseTabLabel()` と同じ形
- ⚠ **AI + シェルの混在タブ**では「AI を残す」の対象が一部だけ（シェルは死ぬ）。
  ラベルがそのタブで起きること全部を言っていない。**件数をラベルに出すか、確認を出す**（a11y / IA が指摘）

### 提案 C'（告知）— **初版を撤回。`intent` 引数に差し替える**

```ts
export type CloseIntent = 'terminate' | 'keep';
summarizeClosingPanes(leaves, intent)   // 'terminate' なら全部 exiting に落とす
closedTabChannel(summary, intent)
```

こうすると:

| 操作 | `summary` | 面 | 文言 |
|---|---|---|---|
| 通常の閉じる | `persistent === 0` | **`announce`**（既存分岐がそのまま効く） | `タブを閉じました。AI も終了しました。会話はサイドバーの「履歴」から再開できます` |
| AI を残して閉じる | `persistent > 0` | **`notice`**（既存の降格判断がそのまま効く） | 現在の文言 + `buildResumeNote()` |

⭐ **これで節8 の判断（5人中4人が指摘して確定させたもの）を1行も消さずに済む。**
しかも**提案 B' がその判断の新しい正当な適用先になる**。初版の「反転」は二重の損失だった。

⭐ **「会話は履歴から再開できます」は a11y ではなく事実**: tmux セッションを kill しても
`~/.claude/projects/*.jsonl` は残るので `claude --resume` で会話は戻る。
**不可逆なのは「実行中の作業」だけ。** この区別を告知に書けば Undo の議論も片付く。

⚠ **IA の追加指摘**: 履歴パネルの既定は「**このフォルダ**」（タスク一覧の既定と逆）。
別フォルダの Claude を閉じた人は、プロバイダを合わせても空の一覧を見る。
節6 が禁じた「一手足りない」が**フォルダ軸で残っている**。

## 4. 実装で絶対に守ること（レビューで初めて出たもの）

### 4-1. ⛔⛔ `ptyKill` ハンドラを `async` にして `disposeEntry()` の前に `await` を挟まない

現在このハンドラは**同期**で、`entry.pty.kill()` → `disposeEntry()` が同一 tick で走る。
そのため `proc.onExit` が発火する頃には `entries.get(ptyId)` が `undefined` になっており、
**Renderer への `ptyExit` 通知も Dock バウンスも意図的に抑止されている**（コメントに明記）。

**ここに `await` を1つ挟むと、タブを閉じるたびに「プロセスは終了しました」バナーが出て Dock が跳ねる。**

### 4-2. `killTmuxSession()` を非同期にする

`spawnSync(..., { timeout: 3000 })` は閉じるホットパスで **Main を最大 3秒 × ペイン数ブロック**する
（`closeTab` は leaf ごとに `pty.kill` を invoke し、IPC ハンドラは直列に処理される）。
`src/main/pty/cwd.ts` の `runLsof()` と同じ**非同期 `execFile` + timeout** にする。

### 4-3. ホバーの塗りを行へ移すときのセレクタ

履歴は全行が押せるので `.history-item:hover` でよかった。**タスクは押せない `<div>` 行が混ざる**ので、
素直に写すと**押せない行までホバーで塗られ、「押せる」の唯一の手がかりが嘘になる**。

```css
.task-item:has(> button.task-item__row):hover { ... }
```

### 4-4. 行が消えたときのフォーカス

終了に成功すると、DOM から消えるのは**フォーカス中の要素そのもの**。
明示的に次のフォーカス先（同グループの次の行、無ければ `.task-group__heading`）へ移さないと `<body>` に落ちる。

### 4-5. E2E への波及（保守レビューが列挙）

| 対象 | 何が起きるか |
|---|---|
| `S90` の「終了せず残っています」検査 | **A で出なくなる。** B と同じ PR に入れないと a11y の関門が一時的に消える |
| `S90` の「live region に流していない」の否定形 | **恒真化する。** 肯定側（`.app-status` が `'ペインを閉じました'`）を足す |
| `S104` | **前提が嘘になるが緑のまま通る**（閉じた直後にセッションを kill しているのに、spec が後から「生きている」状態を作る）。閉じる操作を「AI を残す」に差し替える |
| `S107` | **`Cmd+W` の1経路しか踏んでいない。** Issue #158 と同型の穴。`Cmd+Option+W` を足す |
| `S62` | **1行も壊れない**（2枚のシェルペインで `wrappedInTmux` が false） |
