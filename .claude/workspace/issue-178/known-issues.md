## 1. Issue #174 / #178 本文の「設定ウィンドウを Cmd+W で閉じられない」は既に解消済み

### 症状

Issue 本文が `role: 'close'` を足す動機として挙げている「設定ウィンドウを `Cmd+W` で
閉じられない」は、実コードでは成立していない。

### 原因（判明している場合）

`src/renderer/src/settings/SettingsPanel.tsx` の `useEffect` が `Escape` と `Cmd+W` を
capture フェーズの `keydown` で拾って `onClose()` を呼んでいる。Issue #174 の起票元
（#160 の周の known-issues）が書かれた時点の認識が古いまま転記された可能性が高い。

### 影響範囲

- Issue #178 の周3 の妥当性

### 対処方針

- [x] `architecture.md` の「計画書の前提と実コードのずれ」に記録した
- [ ] 周3 の結論が出たら Issue #178 にコメントで書き戻す

### 優先度

P3（記録のみ）

### ステータス

対処済み（記録した）

## 2. xterm のリンクは、画面が変わってもポインタが同じセルに乗ったままだと古い URL を保持する

### 症状

リンクの上にポインタを置いたまま `clear` して**別の URL**を出し、そのままクリックすると、
**前の URL がブラウザで開く**（実機で再現）。一度リンクから離れて戻すと正しくなる。

### 原因（判明している場合）

`@xterm/addon-web-links` のリンク判定は**ホバーの出入りで更新される**。ポインタが
同じセルに乗り続けている間はバッファの内容が変わってもリンクが再計算されない。
**アプリ側のコードではない**（`useTerminal.ts` はハンドラを1つ渡しているだけ）。

### 影響範囲

- ターミナル内リンクのクリック（誤爆の一種）

### 対処方針

- [ ] 周2 で `Cmd`+クリックを必須にしたことで、**踏む確率は大きく下がっている**
      （素のクリックでは開かないので、`Cmd` を意図して押したときにしか起きない）
- [ ] 直すなら xterm 側（`term.onRender` でリンクキャッシュを捨てる等）だが、
      アドオンの内部に手を入れることになる。**費用に見合わない**

### 優先度

P3

### ステータス

未対処（周2 で発生確率が下がったため、この Issue では踏み込まない）

## 3. リンクのホバー下線は `Cmd` を押していなくても出る

### 症状

`Cmd` を押していないとリンクは開かないが、**ポインタを合わせるだけで下線とポインタ
カーソルが出る**。「押せそうに見えるのに押しても何も起きない」状態になる。

### 原因（判明している場合）

下線とカーソルは xterm 自身が描いており、`WebLinksAddon` のハンドラより手前にある。
`Cmd` の押下に連動させるには `hover` / `leave` コールバックと `keydown` / `keyup` の
追跡を自前で持つ必要がある。

### 影響範囲

- ターミナル内リンクの見た目（アフォーダンスと実際の挙動のずれ）

### 対処方針

- [ ] 周2 の計画ゲートで**ユーザーが「Cmd のみ。ホバーの下線表示は現状のまま触らない」を選択**した。
      連動させるなら見た目が変わるので `/design-review` の対象になる

### 優先度

P3

### ステータス

未対処（意図的に見送り）
