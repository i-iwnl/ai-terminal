## 1. Finder からの実ドラッグ（`dataTransfer.files` 経路）が自動テストの対象外

### 症状

D&D の実装は2経路ある（`dataTransfer.files` -> `webUtils.getPathForFile()` と `text/uri-list`）が、
**E2E が担保しているのは後者だけ**。前者が壊れても S42 は green のまま。

### 原因

`webUtils.getPathForFile()` は Chromium が実ファイルに対して発行した `File` にしかパスを返さず、
`new File([], 'a.txt')` のような合成 File には空文字を返す（例外になる環境もあるので preload 側で握りつぶしてある）。
Playwright から「本物の Finder ドラッグ」を発生させる手段が無い。

### 影響範囲

- Electron のバージョンアップで `webUtils` の API が変わったとき、**気づけるのは人が試したときだけ**
- ただし `text/uri-list` 経路が生きていれば、Finder からのドラッグは（両方のデータを持つため）フォールバックで動く。
  つまり単独で機能が全滅する故障モードではない

### 対処方針

- [ ] Finder から実際にファイルを1つドラッグして、パスが挿入されることを人が確認する
- [ ] 空白入りのフォルダ名を含むパスで、`ls` にそのまま渡して通ることを確認する

### 優先度

P2

### ステータス

未対処（手動確認待ち）。**Issue [#57](https://github.com/i-iwnl/ai-terminal/issues/57) に起票済み**

## 2. ペイン外にドロップしたときの画面遷移抑止に、関門が無い

### 症状

`src/renderer/src/main.tsx` の window レベルの `preventDefault()` を消しても、E2E は全部 green のまま。

### 原因

`dispatchEvent()` で合成した `DragEvent` では、そもそもブラウザ既定のナビゲーションが起きない。
「抑止できていること」を合成イベントで確かめようとすると、**常に成功するテスト**になる。
Playwright には実ファイルの OS ドラッグを起こす API が無い。

### 影響範囲

- 抑止が壊れると、**ターミナル以外の場所（サイドバー・タブバー）にファイルを落としただけでアプリが白画面になり、
  開いていた全タブと PTY を失う**。故障の代償が大きいわりに検出できない

### 対処方針

- [ ] サイドバーとタブバーにファイルを落として、画面が変わらないことを人が確認する
- [ ] 将来 `make e2e-packaged` レーンで OS レベルのドラッグを起こす手段が見つかったら移す

### 優先度

P2

### ステータス

未対処（手動確認待ち）。**Issue [#57](https://github.com/i-iwnl/ai-terminal/issues/57) に 1 とまとめて起票済み**

## 3. ドロップ中の視覚的なフィードバックが無い

### 症状

ドラッグ中にターミナルの上へカーソルを持っていっても、落とせる領域であることが枠や色で示されない
（カーソルの `+` バッジだけが手がかり）。

### 原因

意図的な先送り。ハイライトを足すと `styles.css` を触ることになり、
`/workspace-plan loop` の規約でこの周が `/design-review`（5ペルソナ）の対象になる。
**分割表示（Issue #56）で同じ領域の見た目をまとめて設計するので、そこに合流させる**方が手戻りが少ない。

### 影響範囲

- 発見可能性のみ。機能そのものは動く

### 対処方針

- [ ] Issue #56 の design-review にドロップ時のハイライトを議題として含める

### 優先度

P3

### ステータス

先送り。**個別の Issue は起こさず、Issue [#56](https://github.com/i-iwnl/ai-terminal/issues/56) の
`overview.md` の議題に載せて追跡する**（open な Issue が既にこの領域を持っているため、
別 Issue にすると同じ作業が2箇所で追われることになる）
