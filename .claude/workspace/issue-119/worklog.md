### 設計判断

裁定の全文は `architecture.md` の 4.2 にある。要点だけ:

- **E-4（`selectionBackground` を上げる）は却下。** 3人が独立に「選択範囲の塗りは WCAG 1.4.11 の対象ではない」と結論した。拘束するのは**塗りの上のテキストの 1.4.3** で、`#2f5d8f` にすると既定前景が 5.73 → 4.60 に悪化し、ANSI 16 色のうち 3:1 未満が 9 → 11 色に増える。**改善ではなく退行だった**
- **G（選択中タブ）は白の下辺 2px。** アクセントも `--border-control` も `prefers-contrast: more` の面（#525252）で 3:1 を割る。白だけが 7.81 を保ち、しかも1〜3型で比が動かない
- **A-3（メモ/編集の常時表示）はしない。かつ `visibility: hidden` も採らない。** `visibility: hidden` の要素はフォーカスを受けられないので `:focus-within` が発火できず、キーボードからメモへの唯一の入口が消える。**この点は2人のレビュアーが両方とも見落としていた**
- **F-3（ウィンドウ状態）は `config.json` ではなく `window-state.json`。** `setConfig` → `broadcastConfig` → 全ペインの `term.options.theme` 再代入という経路が実在し、ウィンドウを掴んで動かすたびにこれが走る
- **周1 として「値も見た目も1つも変えず、壊れたときに赤くなる検査を置く周」を先頭に足した。** 現在の 70 spec は、この Issue が変えようとしている4項目を1本も見ていない

### 教訓

- **#20 の Phase/PR 表は 2026-07-31 時点で止まっていた。** PR 15（サイドバー折りたたみ）は #118 で完了、設定の節切り直しは #115 で完了、履歴の範囲見出しは #117 で完了していた。**loop.md が「計画書の現状認識は古くなる」と警告しているとおりで、8件目の実例**
- **「PR #108 と同じ手が使える」という類推が誤りだった。** #108 は `padding-left` で幅を予約したまま当たり判定だけ直したもので、**1px も幅を回収していない**。回収するかしないかで、見た目が変わるかどうかが真逆になる。**前例を引くときは「何をしたか」ではなく「何を維持したか」を見る**
- **`opacity: 0` は3つの性質を持ち、混同しやすい。** (1) レイアウトから外れない、(2) アクセシビリティツリーに残る、(3) **ポインタイベントを止めない**。`.tab-bar__close` は (3) を `pointer-events: none` で潰した実績があるのに、`.history-item__action` には入っていない。**同じ規則が片方にしか適用されていない箇所は、他にもある可能性がある**
- **紙のコントラスト表の誤りが4件目。** design-rules が3件記録している型（「間違っていたのは何と比べるか」）がそのまま再発した。案の 2.03 / 2.53 は実際には 1.96 / 2.45
- **インラインスタイルは詳細度でクラス規則に必ず勝つ。** `style={{width}}` を常時付けると `.sidebar.is-collapsed { width: 0 }` が死に、#118 で入れたばかりの折りたたみが黙って壊れる。**`--sidebar-width` カスタムプロパティ経由にすれば後勝ちの順序が保てる**

### 設計判断

- **`.panel-heading` への畳み込みは周3 へ移した。** `verify-css-substitution.mjs` は
  「トークンを展開したテキストが一致するか」を行単位で見るので、**セレクタを
  まとめると宣言の出現回数が減って必ず FAIL する**。周1 の受け入れ条件
  （PASS）と両立しない。代わりに**畳める前提（2つの宣言が本当に同一であること）**を
  単体テストで固定した。これは畳んだあとも意味を持ち続ける検査ではないが、
  畳む判断の根拠としては十分
- **`selectionBackground` を S40 に足すのはやめた。** 選択範囲は xterm が canvas
  （WebglAddon）に描くので DOM に存在せず、`e2e/fixtures/contrast.ts` の
  `getComputedStyle` ベースの実装では**原理的に測れない**。`src/shared/theme.ts` の
  `contrastRatio()`（S40 と同じ式）を使う単体テストに置いた
- **S74 の主 assert は「現状の不具合の記録」ではなく「周2 の退行の検出」**にした。
  現状は `.history-item__actions` がフロー内にあるのでタイトルとは重ならず、
  9点すべてが resume に届く（green）。**周2 で絶対配置にしたときに、
  `pointer-events: none` を忘れると赤くなる**という形

### 教訓

- **実測すると、レビューの指摘も外れる。** 保守担当レビュアーは
  「`.history-item__action::before`（24px）の当たり判定が meta の行に上下 3.5px ずつ
  はみ出している = 今すでにバグ」と報告したが、**成立していなかった**。
  ボタンの実寸は 14px ではなく **21px** で、`::before` の下端は y=200.5、
  `.history-item__meta` の上端は y=201.5。**1px の余裕がある。**
  design-rules の「要素の実寸を紙で計算しない」が、レビュアーの側でも起きた。
  ただし**余裕が 1px しかない**ことは事実なので、S74 でそこも見るようにした
- **「関門を先に置く」の受け入れ条件を、置こうとしている検査の性質に合わせて選び直す必要があった。**
  `css-substitution-check` PASS を周1 全体の条件にすると、構造のリファクタ
  （`.panel-heading`）が入らない。**同じ周に「値を変えない置換」と
  「構造を変えるリファクタ」を混ぜたのが誤りで、後者を周3 に移した**
- **`#3a6ea5`（選択範囲の塗りを 3:1 に届かせる値）に上げると、単体テスト3件が同時に落ちた。**
  塗りの 3:1 と文字の 4.5:1 が両立しないことが、机上の計算ではなく
  **落ちるテスト**として残った。次に同じ提案が出たときは、この赤が答えになる
