## 2026-07-29 - Phase 1 / PR 1: 既定値を src/shared へ寄せる

### 実施内容

- `src/shared/defaults.ts` を新設し、`DEFAULT_THEME` / `DEFAULT_WEBHOOK` / `DEFAULT_CONFIG` を移した
- `src/main/config.ts` の自前定義を削除し、shared を参照するようにした
- `src/renderer/src/lib/defaults.ts`（#25 で作った暫定の置き場）を削除し、
  `App.tsx` / `SettingsWindow.tsx` は `@shared/defaults` を直接見る形にした
- `config.ts` からの再エクスポートは作らず、テストも唯一の正から直接 import するようにした
- **`coerceConfig({})` が `DEFAULT_CONFIG` と一致することを単体テストで固定した**
- 検証: `make check`（unit 76）/ `make e2e`（38 passed）/ `make e2e-lint`（PASS=279 FAIL=0）
- **`screenReaderMode` を `coerceConfig` から外して、新テストが赤くなることを確認した**

### 設計判断

- **再エクスポートを作らない。** `config.ts` から `DEFAULT_CONFIG` を再エクスポートすると
  同じものへの経路が2本になる。テスト側の import を1行変えるほうが安い
- Renderer 側の `FALLBACK_CONFIG` という名前をやめて `DEFAULT_CONFIG` に統一した。
  「フォールバック」と「既定値」が別物に見えていたのが、そもそも二重化を許した一因

### 教訓（該当する場合）

- **型が守ってくれない二重化がある。** 設定項目を増やすとき、`AppConfig` と `DEFAULT_CONFIG` は
  型で守られるが、**`coerceConfig` への追加漏れは型では検出できない**
  （返り値の型は満たしたまま、その項目だけが常に undefined になる）。
  空オブジェクトを食わせて既定値と一致するかを見る1行で、そこを機械化できた
- **「見た目の変化ゼロ」は `git status docs/images/` で確認できる。**
  主張するだけでなく、画像に差分が出ていないことを実際に見た
