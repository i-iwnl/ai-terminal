# Status - ワークスペース一覧と状態の確認

現在存在するワークスペースを一覧し、対応するGitHub Issueの状態と突き合わせる手順。**セッション再開時はこの操作から始める。**

## トリガー

- 現在の進捗を確認したいとき / 次に何をすべきか知りたいとき
- セッション再開時のコンテキスト復帰

## 手順

### 1. ワークスペースの検出

```bash
ls -d .claude/workspace/issue-*/ 2>/dev/null
```

存在しない場合は `init` を促す。

### 2. 各ワークスペースのサマリ生成

検出した `.claude/workspace/issue-<番号>/` ごとに:

1. `overview.md` から: Issueへのリンク、完成条件の達成状況、次アクション
2. `known-issues.md` から: 未解決の問題数、P0/P1の問題
3. `worklog.md` から: 最新エントリの日付と「次に再開するとき最初に読むべきこと」欄

### 3. Issueのopen/closedとの突合

```bash
gh issue list --state all --json number,state,title --limit 100
```

各ワークスペースの Issue番号と `state` を突き合わせる。

- **ワークスペースが残っているのにIssueが `CLOSED`** になっているものは警告として出す（ワークスペースの締め忘れ、または既に片付いたのに残骸が残っている可能性）
- Issueが見つからない（削除・番号違い）場合もあわせて警告する

### 4. 出力フォーマット

```
## ワークスペース一覧

### issue-<番号>: <Issueタイトル>（<Issue state>）
- 完了条件: {N}/{M}
- 未解決の問題: {K} 件 (P0: {a}, P1: {b})
- 最終作業日: {worklog.md の最新エントリ日付}
- 次に再開するとき: {worklog.md 最新エントリの当該欄}

### 警告
- issue-<番号>: Issueがclosed済みだがワークスペースが残っている
```

## 注意事項

- 読み取り専用操作（ファイルの変更は行わない）
- `gh` コマンドが失敗した場合は、Issue突合を省略してワークスペース側の情報のみで出力する（アプリの都合ではなくskill運用の話だが、`gh` 不通時に処理を止めない方針は同じ）
