# Worklog テンプレート

生成時は `{...}` をタスク固有の内容に置換する。エントリは時系列で追記していく（過去のログは編集しない）。

**「次に再開するとき最初に読むべきこと」は毎エントリ必須。** セッションが切れても文脈を復元できることがこのファイルの存在理由。`status` 操作は最新エントリのこの欄を提示する。

---

```markdown
# Worklog

時系列の作業ログ。**設計判断の根拠**と**学んだ教訓**を中心に記録する。
コード差分は git log を参照、現状の構造は `architecture.md` を参照。

---

## {日付} - {作業タイトル}

### 実施内容

- {実施した作業の箇条書き}

### 設計判断

- {判断内容}: {根拠}

### 教訓（該当する場合）

- {ハマりどころや学びの記録}

### 次に再開するとき最初に読むべきこと

- {このエントリ時点で、次のセッションが最初に確認すべきこと。例: 未完了のタスク・保留中の判断・直前に見ていたファイル}

---

<!-- 以降、作業のたびにセクションを追記 -->
```
