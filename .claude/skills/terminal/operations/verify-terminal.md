# ターミナルとして本当に使えるか手動検証する

xterm.js + node-pty の組み合わせが「普段使いのターミナル」として成立しているかを人手で確認する手順。**GUI 操作が必須のため自動テストでは代替できない。** Phase 1（docs/PLAN.md）の受け入れ基準をそのまま使う。

## 事前準備

起動コマンドの唯一の正はルート [CLAUDE.md](../../../../CLAUDE.md) と Makefile。この skill 側では手順を再掲しない。

- `make dev` … 通常起動（DevTools が別ウィンドウで自動的に開く）
- `make dev-quiet` … DevTools を開かずに起動する
- `make dev-debug` … Main プロセスのデバッガを有効にして起動する（PTY の起動引数を追いたいとき）

## ステップ 1: チェックリストを1項目ずつ確認する

各項目を実際に操作して確認する。全項目が満たされるまで「検証完了」扱いにしない。

- [ ] `vim` でファイルを開いて編集・保存でき、画面が崩れない
- [ ] `htop` が正しく描画され、リアルタイム更新される
- [ ] 日本語を IME で入力でき、変換中の下線・候補表示が崩れない
- [ ] 日本語・絵文字を含む出力（`ls` の日本語ファイル名や絵文字入りの文字列など）で文字幅がずれない
- [ ] ウィンドウをリサイズしてもターミナルの表示が追従する
- [ ] `Cmd+C` / `Cmd+V` でコピー・ペーストができる
- [ ] `Ctrl+C` で実行中のプロセス（`sleep 100` 等）を止められる
- [ ] `ls --color` の色が正しく出る

これらのうちどれか1つでも崩れると「普段使いのターミナル」として成立しない、という優先度で扱う（docs/PLAN.md の Phase 1 が最優先マイルストーンとされている理由）。

## ステップ 2: 挙動がおかしいときの切り分け

**まず DevTools を開く（`Cmd+Option+I`）。** Renderer 側（xterm.js やキー入力処理）で起きたエラーは Main プロセスのターミナル出力には出ない。`make dev-quiet` で起動した場合は DevTools が開いていないため気づけない点に注意する。

- PTY が起動しない・`posix_spawnp failed` が出る -> [../reference/pty-pitfalls.md](../reference/pty-pitfalls.md)
- 文字幅・IME・キー入力まわりがおかしい -> [../reference/xterm-setup.md](../reference/xterm-setup.md)
- それ以外の症状（preload が読み込まれない等）-> [/electron-ipc](../../electron-ipc/SKILL.md)

## DoD（完了条件）

- ステップ1のチェックリストが全項目 done であること
- 崩れた項目があれば、原因を切り分けて該当する reference に沿って修正し、**再度チェックリストを通しで確認してから**完了扱いにする（1項目直して終わりにしない）
